Docs

Breakpoint runs on any machine with Python 3.10+ and MuJoCo. No GPU, no PyTorch, no API keys.

Install

git clone https://github.com/AyanBhardwaj1/RL-Robot.git
cd RL-Robot
pip install -e '.[dev]'
pytest -q

Command line

Every command is python -m breakpoint <command>. Commands that judge a policy exit non-zero when it fails, so they can gate CI.

CommandWhat it does
compile "…"Plain English (or --image photo.jpg) to a validated scenario JSON.
run --text "…"Roll out one scenario; exit 1 if the robot falls or stalls.
train --steps 420000Train a residual PPO policy on one CPU core, keeping the best checkpoint judged without noise.
audit --policy pBreaking points, nominal runs, adversarial hunt, compound stress, red team and deployment odds, as an HTML report.
harden --policy p --profile sidewalk,teleopHunt failures, shrink them to tests, fine-tune on them and the target places, re-audit.
regress --suite dirReplay saved counterexamples on 3 seeds.
deploy --profile warehouse --max-fail 0.1Failure rate and 95% upper bound for each place.
redteam --policy pCompound-stress pairs and realistic multi-stressor attacks.
leaderboard cpg a.npz b.npzUp to 4 policies audited side by side with identical seeds.
certify --policy p --min-score 80Readiness certificate with policy hash and toolchain versions.
serveThe local lab with live shove mode over a WebSocket.

Policy specs

SpecMeaning
cpgThe open-loop trotting gait with no learning. Immune to lag, weak against shoves.
runs/v2/policy_v2.npzA residual PPO policy saved by train or harden.
gated:<spec>That policy behind the latency gate: full strength to 40 ms, faded to the gait by 80 ms.
py:module:factoryYour own controller: factory() returns a callable from a 47-number observation to 12 joint corrections in [-1, 1].

Scenarios

Every world, whether typed, photographed, proposed by an LLM or found by the search, passes through one schema that clamps each value to physical bounds.

{
  "terrain": "rough",        // flat | rough | slope | stairs
  "roughness": 0.03,         // m, 0–0.08
  "slope_deg": 0,            // −20 to 20, uphill positive
  "step_height": 0,          // m, 0–0.10
  "friction": 0.6,           // 0.05–2
  "payload_kg": 2.5,         // 0–8
  "motor_strength": 1.0,     // × torque, 0.2–1.5
  "latency_steps": 2,        // × 20 ms, 0–6
  "obs_noise": 0.02,         // σ, 0–0.5
  "pushes": [{ "t": 2.0, "force": 80, "direction_deg": -90, "duration": 0.1 }]
}

A push’s direction_deg is the force direction in the robot’s frame: 0 pushes it forward (a shove from the rear), +90 toward its left (a shove from its right), −90 toward its right (a shove from its left).

Web API

The hosted lab calls these endpoints. They are stateless, size-capped and documented interactively at /api/docs.

EndpointBodyReturns
POST /api/compile{"text"}Scenario and how it was parsed
POST /api/compile_image{"image_b64", "caption"}Scenario from a ground photo (3 MB max)
POST /api/simulate{"scenario", "policy", "seed"}Outcome, explanation, geom poses per frame (10 s max)
POST /api/probe{"policy", "axis"}Breaking point on one stress
POST /api/deploy{"policy", "profile", "trials"}Failure rate, bound and causes (12 worlds max)
GET /api/policies, /api/profiles, /api/axes–Available options
 
curl -X POST https://<this-site>/api/simulate -H 'Content-Type: application/json' \
  -d '{"policy": "gated-v2field", "scenario": {"terrain": "stairs", "step_height": 0.07}}'

How scores work

  • Pass: no fall (tilt past 65° or body within 11 cm of the ground) and at least 35% of the commanded distance.
  • Breaking point: the largest stress passed on every seed, found by bisection; pushes are tested at 4 points in the stride and scored by the worst.
  • Readiness score: 45% margin index (pushes 40%, other stresses 60%) + 40% nominal pass rate + 15% adversarial (penalises failures found at low severity).
  • Grades: 85+ field-ready, 70+ supervised, 50+ lab-only, below that not ready.
  • Bounds: exact binomial with zero failures (≈ 3 / n), Wilson score otherwise, at 95%.

Limits

  • The robot is generic, not a calibrated model of a product, so numbers compare policies rather than certify hardware.
  • Search can’t prove a failure doesn’t exist; reports always state the budget.
  • The hosted lab runs on serverless functions: no live WebSocket shove mode (use arrow keys during playback instead), and odds use 12 worlds rather than 60.
