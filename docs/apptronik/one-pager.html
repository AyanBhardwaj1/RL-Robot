What it does

  • Breaking points. Bisects 17 stresses (shoves at 4 gait phases, slope, stairs, friction, payload, weak motors, latency, noise) to the exact edge the policy survives.
  • Failure hunting. Cross-entropy search for the mildest failing worlds, a MAP-Elites atlas of failure types, and shrinking to minimal JSON regression tests.
  • Hardening. PPO, written from scratch in numpy, replays failures and target deployment worlds; a checkpoint ships only if it beats the start.
  • Deployment odds. Failure rate per site profile with a 95% upper bound and causes; a hazard log turns them into risk ratings with verify commands.
  • Humanoid lab. Capture-point push recovery for a 72 kg biped, a wheeled-base comparison, and odds by job, in Python, a browser port and a C++17 port held equal by tests.

What it found

  • A policy that walked in noisy training stood still when run for real, and scored below the gait it was built on.
  • A second hardening round overfit; a fresh audit caught it.
  • Training could not remove latency failures; gating the learned residual on measured link latency did.
  • Legs vs wheels: the wheeled base survives 1.5× bigger shoves from the front and 2.7× from the side, but fails 47% of home-care routes (stairs); the biped fails 0% there, but 13% of trailer shifts (mostly slips).
  • A capturability map and an independent review exposed three modelling errors (a non-causal latency model, a swing foot that still held weight, ankles that ignored lag); each fix made the biped’s odds worse and more honest.
  • The C++ controller step costs about 1 µs; stock-kernel wake-up jitter reaches 4.9 ms, which is the case for PREEMPT_RT.
